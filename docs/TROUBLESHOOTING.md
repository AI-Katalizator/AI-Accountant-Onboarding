Проверки среды после разворачивания инфраструктуры. Установка описана в [SKILL.md](../SKILL.md). Требования к компьютеру и портам — в [технических требованиях](TECHNICAL_REQUIREMENTS.md).

Работа с задачей и черновиком — в [инструкции для бухгалтера](INSTRUCTION_ACCOUNTANT.md). Подготовка базы 1С — в [инструкции для ИТ-специалиста](INSTRUCTION_IT_1C.md).

## Как проверить, что Docker запущен?

n8n и docreader работают в Docker. Docker Desktop запущен и готов к работе. На Windows используется бэкенд WSL2. Автозапуск при входе в систему поднимает среду после перезагрузки компьютера.

## Как проверить, что n8n запущен?

Адрес n8n: http://localhost:5678

Служебная страница http://localhost:5678/healthz открывается и отвечает без ошибки. Порт 5678 занимает n8n. Чужой сервис на этом порту при установке не останавливают.

Перезапуск контейнера выполняют из папки `docker` пакета:

```text
docker compose restart n8n
```

Учётную запись для входа в n8n создают при установке. Пароль в файлы пакета не записывают.

## Как проверить, что модель Ollama установлена?

Для распознавания сканов используется модель `qwen2.5vl:7b-16k`. Ollama установлена на компьютере, вне Docker, и слушает порт 11434.

Модель ставится по [SKILL.md](../SKILL.md), шаг 2.2: сначала `qwen2.5vl:7b`, затем создаётся имя `qwen2.5vl:7b-16k`. Объём загрузки — около 6 ГБ.

Самопроверка на шаге 4 того же файла подтверждает, что Ollama запущена и модель загружена.

## Как проверить, что docreader отвечает?

Адрес проверки: http://localhost:8011/health

В ответе есть `ok`. Самопроверка ожидает версию 0.2.x. В `docker-compose.yml` сервис называется `docreader`, порт — 8011.

Перезапуск из папки `docker` пакета:

```text
docker compose restart docreader
```

Docreader готовит таблицу реквизитов и прикладывает её к задаче в 1С.

## Как проверить доступ к OData 1С?

К адресу веб-публикации добавляется путь `/odata/standard.odata/$metadata`. Пример для публикации `http://localhost:8081/base`:

```text
http://localhost:8081/base/odata/standard.odata/$metadata
```

Браузер запрашивает имя и пароль пользователя помощника. Пароль вводите в окне браузера. В файлы и в переписку его не копируют.

Успешный ответ — описание метаданных OData в формате XML.

| Код | Значение |
|---|---|
| 401 | Неверный логин или пароль, либо вход этому пользователю не разрешён |
| 404 | Неверный адрес публикации или стандартный интерфейс OData не включён |

Проверка из пакета. Адрес и имя пользователя подставляете свои:

```text
python3 helpers/check_odata.py http://localhost:8081/base/odata/standard.odata AI
```

Скрипт запрашивает пароль в скрытом поле, на экран его не выводит и показывает, какие объекты видны. Состав объектов — раздел 3 [инструкции по 1С](1C_publikaciya_OData_AI.md). Порядок публикации — в [инструкции для ИТ-специалиста](INSTRUCTION_IT_1C.md).

## Как передаётся скан на распознавание?

Файл помещают в папку входящих, указанную при настройке. Распознавание выполняет модель `qwen2.5vl:7b-16k`. Результат сценарий записывает в задачу в 1С, исходный файл прикреплён к этой задаче.

На компьютере Mac с процессором Intel распознавание сканов выполняется медленнее. На распознавание передают чёткий скан.

## Где посмотреть, каких сведений не хватило для черновика?

В тексте задачи в 1С записан ход работы и перечень недостающих сведений. Документ дооформляют в 1С и проводят. Подробности — в [инструкции для бухгалтера](INSTRUCTION_ACCOUNTANT.md), раздел «Типовые ситуации».

## Как проверить, что вложение задачи хранится в томе?

Файлы 1С хранятся в томах на диске. Тестовое вложение к задаче появляется файлом в каталоге тома. Полный путь каталога записан в профиле: `folders.file_volume_host`. Условие описано в [технических требованиях](TECHNICAL_REQUIREMENTS.md), раздел 3, и в [инструкции для ИТ-специалиста](INSTRUCTION_IT_1C.md).
