# Настройка 1С для ИИ-бухгалтера

Нужно один раз. Если у вас 1С во фреше или у франчайзи — отправьте им этот файл, разделы 1–3 делают они.
Если 1С стоит в вашем контуре (ПК, сервер фирмы или ВМ) — ассистент установки проведёт по шагам.

## 1. Публикация базы на веб-сервере
Чтобы ИИ-бухгалтер мог обращаться к 1С, база должна открываться по адресу в браузере.
1. Нужен веб-сервер: на Windows — IIS или Apache, на Mac — Apache.
2. Запустите 1С в режиме «Конфигуратор» от имени администратора.
3. Меню «Администрирование» → «Публикация на веб-сервере».
4. Имя — коротко латиницей, например `base`. Поставьте галочку
   **«Публиковать стандартный интерфейс OData»**. Нажмите «Опубликовать».
5. Проверка: в браузере открывается `http://localhost/base` (или с портом, например `:8081`).

## 2. Пользователь AI
1. В 1С: «Администрирование» → «Настройки пользователей и прав» → «Пользователи» → «Создать».
2. Имя: `AI`. Задайте пароль (сохраните его — он понадобится только для ввода в n8n).
3. Галочка «Вход в программу разрешён», аутентификация 1С:Предприятия.
4. Права: профиль «Бухгалтер» и, если в базе есть, «Права для REST/OData».
   ИИ-бухгалтер создаёт только черновики — проводит документы человек.

## 3. Какие объекты открыть для OData
«Администрирование» → «Обслуживание» → «Настройка автоматического REST-сервиса»
(или обработка «НастройкаСоставаСтандартногоИнтерфейсаOData»). Отметьте:
- Справочники: Контрагенты, Договоры контрагентов, Номенклатура, Банковские счета, Статьи ДДС,
  Организации, Пользователи;
- Документы: Поступление (акты, накладные, УПД), Поступление на расчётный счёт,
  Списание с расчётного счёта, Платёжное поручение, Счёт на оплату поставщика,
  Приходный и расходный кассовые ордера, Авансовый отчёт.
Нажмите «Сохранить». Ассистент проверит, что всё видно.

## 4. Заглушка «Оплата по счёту»
«Справочники» → «Номенклатура» → «Создать». Наименование ровно: **Оплата по счёту**.
Вид — «Услуги». Сохраните. Она нужна, когда в документе нет понятной позиции.

## 5. Хранение файлов в томах (обязательно)

Помощник прикладывает к задачам исходные файлы и служебные `rules.md` у договоров. Если файлы 1С хранятся «в базе», база раздувается, а сценарии не могут надёжно класть вложения по пути на диске. Поэтому для AI-Katalizator нужно **хранение в томах на диске**, не в самой базе.

1. В 1С: «Администрирование» → «Настройки работы с файлами» (или «Хранилище файлов» / тома — формулировка зависит от релиза БП).
2. Включите хранение файлов **в томах на диске** (не «в информационной базе»).
3. Два варианта пути:
   - **Тома ещё не было** — создайте каталог рядом с папками документов n8n (как в нашем рабочем контуре), например `…/Документы/Том 1С` или соседнюю папку у `HOST_FILES_DIR`. Укажите этот путь в настройке тома 1С. Ассистент установки может предложить и создать каталог с вашего «да».
   - **Том уже есть** — не переносите базу: сообщите ассистенту **полный путь** к каталогу тома на диске (тот, что прописан в 1С). Он запишет его в профиль (`folders.file_volume_host` / `file_volume_n8n` и `file_storage`), чтобы сценарии клали вложения и `rules.md` именно туда.
4. Проверьте: создайте тестовое вложение к любой задаче в 1С — файл должен появиться в каталоге тома на диске, а не только «внутри» базы.

Без настроенного тома установка среды не считается завершённой: OData и веб-публикация сами по себе для вложений и правил учёта недостаточны.
