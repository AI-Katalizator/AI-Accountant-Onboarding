# Технические требования — AI-Katalizator Onboarding

Документ для IT-специалиста клиента: что ставится, какие ресурсы и доступы нужны, что остаётся в контуре компании.

## 1. Платформа

| Параметр | Требование |
|---|---|
| ОС | macOS 13+ на Apple Silicon (M1 и новее) **или** Windows 10/11 64-бит |
| Mac Intel | Работает, но распознавание сканов заметно медленнее |
| ОЗУ | минимум 16 ГБ, рекомендовано 32 ГБ. Менее 16 ГБ — не поддерживается |
| Диск | ≥ 30 ГБ свободно (модель ~6 ГБ, образы Docker, документы) |
| Docker Desktop | установлен и запущен; на Windows — бэкенд WSL2; Resources → память ≥ 4 ГБ |
| Python 3 | для скриптов проверки (`helpers/`) |
| Права | установка ПО и запуск Docker под пользователем, который будет работать со средой |

Проверено: macOS (тестовый стек, 28.10.2026). Windows — пакет рассчитан, сквозная проверка ещё не проводилась.

## 2. Что устанавливается

| Компонент | Как | Порт |
|---|---|---|
| n8n 2.39.5 | Docker (`ai-accountant/n8n` на базе `n8nio/n8n:2.39.5`) | `127.0.0.1:5678` |
| docreader 0.2.0 (распознавание документов) | Docker, сборка из `docker/docreader` | `127.0.0.1:8011` |
| Ollama + модель `qwen2.5vl:7b-16k` | Нативно, вне Docker | `11434` |
| Community-ноды n8n: Safe File Move, PDF Toolkit | В том данных n8n, не в образ | — |

Порты 5678, 8011, 11434 должны быть свободны либо заняты именно этими сервисами. Порты Docker публикуются только на `127.0.0.1`; контейнеры обращаются к хосту (Ollama, 1С) через `host.docker.internal`.

Безопасность n8n: узел Execute Command отключён (`NODES_EXCLUDE`); внешние модули в Code-узлах ограничены (`NODE_FUNCTION_ALLOW_EXTERNAL`, только xlsx).

## 3. 1С

К базе три обязательных условия (без любого из них сценарии не собрать полноценно):

1. **Веб-публикация** базы.
2. **OData** (`/odata/standard.odata`) и пользователь 1С (например, `AI`) с правами на чтение справочников/документов и запись непроведённых документов.
3. **Хранение файлов в томах на диске** (не в информационной базе): сюда 1С кладёт вложения к задачам и служебные файлы вроде `rules.md` у договоров. Раздувать базу бинарниками нельзя — на пути тома фактически держится работа помощника.

Состав объектов OData и пошаговая настройка (включая тома): [1C_publikaciya_OData_AI.md](1C_publikaciya_OData_AI.md).  
Конфигурацию 1С не меняем. Документы создаются только как непроведённые черновики.

## 4. Папки и данные

- Папка документов организации (`HOST_FILES_DIR`) — монтируется в n8n (входящие, обработанные и т.д.).
- **Каталог тома 1С на диске** — либо уже настроенный в 1С путь (записать в профиль), либо новый каталог рядом с папками документов n8n, который 1С указывает как том. Путь должен быть доступен и 1С, и (при необходимости) сценариям через профиль `file_volume_*`.
- Папка данных n8n (`N8N_DATA_DIR`) — bind-mount: сценарии, credentials, ноды. Включите её в резервное копирование.
- `~/ai-accountant/profile.json` — несекретные реквизиты организации и настройки (без паролей и ключей), в том числе режим и путь тома файлов.

## 5. Сеть

- На время установки — интернет: Docker Hub, PyPI/npm (сборка образов, ноды), загрузка модели Ollama.
- В работе: доступ с машины к веб-публикации 1С; опционально — API DaData (ключ клиента) для проверки контрагентов.
- Входящие соединения из интернета не требуются.

## 6. Что остаётся в контуре клиента

Документы, данные 1С, credentials n8n, модель и результаты распознавания — всё на машине/сервере клиента. Разработчик не получает доступа, если клиент сам его не предоставил (например, сеанс удалённой установки).

## 7. Что мы НЕ делаем

- Не предоставляем хостинг и не храним данные клиента.
- Не меняем конфигурацию 1С и не проводим документы.
- Не запрашиваем пароли в чате — секреты вводятся в скрытые поля и Credentials n8n.
- Сценарии учёта и MCP 1С в этот пакет не входят.

## 8. Обновление и откат

`git pull` → при изменениях в `docker/` пересборка `docker compose up -d --build`. Тома данных не удаляются. Откат — предыдущий тег/архив и повторная сборка.
