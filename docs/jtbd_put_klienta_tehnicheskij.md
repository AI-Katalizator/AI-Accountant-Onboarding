## Детали по шагам

### 0. Покупка / доступ
- **Клиент:** оплата или пилотный доступ.
- **Мы:** пакет установщика среды + доступ к сценариям (сейчас удобный канал — приватный/публичный GitHub или архив `ai-accountant-setup-….tgz`).
- **Для открытого GitHub:** публикуем путь + пакет среды **без** секретов и без клиентских баз; интерес рынка смотрим по звёздам/issues.

### 1. Инфраструктура
- **Клиент:** «Установи ИИ-бухгалтера» → согласия на Docker / Ollama / папки / compose.
- **Мы:** `installer/SKILL.md`.
- **Итог:** n8n 2.39.5, docreader, Ollama+модель, папки, ноды Safe File Move + PDF Toolkit, самопроверка.
- **Не входит:** импорт учётных сценариев.

### 2. Подготовка базы 1С
- **Клиент (или его 1С-специалист):** публикация, OData, пользователь AI с нужными правами, заглушка номенклатуры «Оплата по счёту».
- **Мы:** инструкция `1C_publikaciya_OData_AI.md`; проверка связи — `helpers/check_odata.py` (пароль только у клиента).
- **Важно:** первый запуск — на **копии** базы.

### 3. Профиль на диске
- **Клиент:** отвечает блоками (организация, папки, исполнители задач…).
- **Мы:** пишем `~/ai-accountant/profile.json` без секретов; Credentials клиент создаёт сам.
- **Итог шага:** файл профиля. В workflow n8n он **ещё не попал**.

### 4. Онбординг клиента (= первый «сценарий установки»)
Смысл: один раз превратить `profile.json` в рабочий workflow профиля в n8n.

- **Клиент:** подтверждает действие ассистенту (не заполняет поля вручную в UI n8n).
- **Мы (нужно сделать):**
  1. Шаблон workflow `0.1 Профиль Организации` (плоский формат как IVENT).
  2. Скрипт/шаг ассистента: подставить поля из `profile.json` → готовый JSON workflow.
  3. Импорт в n8n (`docker exec` / API) + publish.
  4. В профиль (или в Set онбординга) заложить поле **даты отсечения** для шага 6 — если клиент её уже назвал на этом шаге.
- **Итог:** все учётные сценарии вызывают один профиль; клиент JSON руками не правит.

### 5. DaData
- По желанию; инструкция готова.

### 6. Онбординг агента: расчёты с поставщиками
Рабочее имя (для упаковщика можно смягчить):  
**«Онбординг агента: расчёты с поставщиками»**  
(не «по актам» — обход учёта по сч. 60 / договорам; акты — уже боевой сценарий).

- **Зачем:** один раз наполнить `rules.md` по живым проведениям, особенно если договоры «Основной договор».
- **Клиент:**
  - Запускает онбординг (кнопка/ассистент/ручной Run в n8n — UX упакуем позже).
  - **Обязательно указывает дату отсечения** анализа кредиторки/открытых расчётов.
- **Дата (техническое решение на сейчас):**
  - Спрашиваем: «С какой даты разобрать расчёты с поставщиками (сч. 60)?»
  - Подсказка по умолчанию: **последняя отчётная дата** (конец прошлого квартала / года — формулировку уточним), не «всегда 1 января», если клиент не выбрал.
  - Пока UI нет — дату можно задать вручную в профиле / в параметре запуска сценария.
  - Дата сохраняется в профиле (например `onboarding.suppliers_cutoff_date`) и читается сценарием онбординга.
- **Мы:**
  - OData/отбор: обороты/остатки по 60, контрагент → договор → последние проведённые поступления услуг/товаров.
  - Для каждого договора без `rules.md` (или без пометки «Изменено: бухгалтером») — создать человекочитаемый `rules.md` в томе договора.
  - Отчёт в задачу(и) 1С: создано N, пропущено M, спорные K.
  - Права бухгалтера: правки в файле приоритетны; агент не перезаписывает «Изменено: бухгалтером».
- **Не делает:** распознавание PDF, проведение документов.

### 7. Боевой сценарий учёта (например акты/УПД)
- **Клиент:** кладёт файл во входную папку из профиля.
- **Мы:** распознавание → задача в 1С → черновик поступления.
- **Слои внутри сценария:**
  1. Есть `rules.md` у договора → по нему.
  2. Нет → **прецеденты** (запасной аэродром для договоров, не попавших в онбординг).
  3. Позже → ИИ по учётной политике / НСИ.
- Комплекты акт+СФ и создание `СчетФактураПолученный` — отдельные доработки хвоста (в бэклоге).

### 8. Проведение бухгалтером
- **Клиент:** проверяет, правит, проводит.
- **Мы (следующий контур):** наблюдатель «документ агента стал Проведен» → дописать/создать `rules.md` из фактических счетов/статей (не перетирая правки бухгалтера).

### 9. Обычная работа
- Большинство документов — по правилам; исключения — в задаче 1С простым языком.
- Повторный онбординг агента — по желанию (новые договоры, смена даты).
